## زمینه

پروژه از قبل زیرساخت نیمی از نیاز را دارد (از تغییرات قبلی): نقش `coach` روی سرور، تخصیص برنامه‌ی ورزشی به شاگرد با پوشش فقط‌خواندنی سمت ورزشکار، پنل ادمین با دکمه‌ی «Make coach»، و ورود ورزشکار به مربی فقط از طریق کد دعوتِ مربی. طبق انتخاب شما: **باشگاه‌دار با متغیر محیطی `ADMIN_UIDS` تعریف می‌شود** (وضع موجود) و **اتصال ورزشکار به مربی فقط از طریق تخصیص باشگاه‌دار** انجام می‌شود (جریان کد دعوت مربی حذف می‌شود).

## تغییرات سرور — `api/server.js`

1. **مسیر جدید `POST /api/admin/user/coach`** با بدنه `{ id, coachId }` (برای جداسازی `coachId: null`):
   - اعتبارسنجی: کاربر هدف موجود و از نوع member؛ مربی باید موجود و `isCoach` باشد و خودِ شخص نباشد.
   - اتصال: حذف لینک قبلی (یک مربی برای هر ورزشکار)، ایجاد `coachLink` جدید، حذف برنامه‌های تخصیصی مربی قبلی از این عضو (`coachAssignments`)، ست‌کردن `member.coachId`، `saveDb()`.
   - جداسازی: حذف link + assignment + `member.coachId`.
2. **مسیر جدید `POST /api/admin/user/admin`** با بدنه `{ id, admin }`: ارتقا/تنزل ادمین با گاردها — خود را نمی‌توان تغییر داد، ادمین‌های تعریف‌شده در `ADMIN_UIDS` قابل تنزل نیستند (خطای «managed by server configuration»).
3. **حذف `POST /api/coach/invites/new`** و حذف شاخه‌ی `invite.coachId` از `/api/register`؛ مهاجرت بوت: دعوت‌نامه‌های دارای `coachId` از `db.json` قدیمی یک‌بار پاک شوند (الگوی موجود passkey در خط 38).
4. **غنی‌سازی داده‌ی پنل:** در `GET /api/admin/users` و `GET /api/admin/user` فیلد `coach: {id, name} | null` برای هر عضو، و در detail فیلد `envAdmin` (تا UI دکمه‌ی تنزل را برای ادمین محیطی نشان ندهد).
5. بقیه‌ی مسیرها (`/api/coach/clients`, `/api/coach/client`, `/api/coach/assignment`, cleanup تنزل مربی در `/api/admin/user/role`) بدون تغییر می‌مانند — چون همان `coachLinks` را می‌خوانند، با مکانیزم جدید خودکار کار می‌کنند.

## تغییرات فرانت‌اند

- **`frontend/src/views/Admin.jsx`** (انگلیسی‌محور، بدون i18n — طبق طراحی فعلی):
  - در `UserDetail`: بخش «Coach» با نمایش مربی فعلی، دکمه‌ی Assign coach → شیت انتخاب مربی (لیست کاربران `role==='coach'` با الگوی `.lrow tap` از `SelectRow` در `components/ui.jsx:251`) و دکمه‌ی Remove coach با `confirmSheet`.
  - دکمه‌ی Make admin / Remove admin (با confirm برای تنزل؛ مخفی برای `envAdmin`).
  - در لیست کاربران، نام مربی کنار نقش در خط `.ss`.
- **`frontend/src/views/Coach.jsx`**: حذف کارت «Invite a club member» و تابع `makeInvite`؛ متن حالت خالی به «باشگاه‌دار باید ورزشکاران را به شما تخصیص دهد» تغییر کند.
- **`frontend/src/views/Login.jsx`**: حذف خط راهنمای «A coach invite links your account…».
- **`frontend/src/views/Settings.jsx`**: ردیف «My coach» (نام مربی از `S.coachProgram`) در بخش Account برای ورزشکارِ تحت مربی.
- **رفع نقص‌های مرتبط پیدا‌شده:** `sheets.jsx` تابع `AddToRoutine` روتین‌های `coachManaged` را از اهداف حذف کند؛ `Home.jsx` نواری هفته در حالت coachProgram شیت override باز نکند؛ `lib/plan-share.js` (`buildPlanBundle`) روتین‌های coachManaged را از خروجی اشتراک حذف کند.
- **`frontend/src/locales/fa.js` و `es.js`**: کلیدهای جدید (مربی من، …) اضافه، کلیدهای دعوت مربی حذف، و کلیدهای دو فایل هم‌تراز شوند — این کار تست i18n که از قبل می‌شکست را هم سبز می‌کند.

## مستندات

به‌روزرسانی بخش نقش‌ها در `README.fa.md`، `README.md` و `docs/SELF_HOSTING.md`: باشگاه‌دار = `ADMIN_UIDS`؛ باشگاه‌دار از پنل، مربی تعیین و برای هر مربی از بین ثبت‌نام‌کرده‌ها ورزشکار تخصیص می‌دهد؛ کد دعوت مربی حذف شده.

## راستی‌آزمایی

1. `npm test` — همه سبز (شامل i18n که با هم‌ترازی fa/es درست می‌شود).
2. `npm run build` — بیلد بدون خطا.
3. تست API با سرور محلی (`DATA_DIR` موقت و `ADMIN_UIDS`): ثبت‌نام ۳ کاربر → ارتقای مربی → تخصیص ورزشکار → `PUT /api/coach/assignment` → `GET /api/data` ورزشکار باید `coachProgram` را برگرداند؛ جداسازی و تنزل مربی باید لینک و برنامه را پاک کند.
